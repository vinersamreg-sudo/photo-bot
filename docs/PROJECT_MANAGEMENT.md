## Инструменты

- Kanban-backlog, приоритеты P0/P1/P2 и короткие production-спринты.
- GitHub и GitHub Actions для версий, проверок и контролируемого deploy.
- Python 3.12, `unittest`, SQLite и приватное файловое хранилище для backend.
- MAX Bot API, OpenAI image editing и Robokassa для продуктового контура.
- Hetzner VPS, nginx, systemd, Let's Encrypt, healthcheck и backup/restore для
  эксплуатации.
- Решения фиксируются в документации репозитория, а доказательства проверок — в
  аудитах и runbooks.

## Контроль сроков и выполнения задач

Проект был разделён на три этапа:

1. **01–05.07 — анализ:** scope, требования, ограничения и первичный реестр
   рисков.
2. **06–20.07 — реализация:** MAX-сценарий, preview, Gallery, платежи, сайт и
   инфраструктура.
3. **21–31.07 — приёмка MVP:** E2E, реальная оплата, выдача оригинала,
   production-проверки и публичный запуск.

Для задач задавались критерии приёмки. Переход между этапами подтверждался не
наличием кода, а цепочкой `профильные тесты → CI → deploy → healthcheck → E2E`,
когда внешний контур нельзя было проверить локально. Открытые задачи не
маскируются статусом завершённого функционала и ведутся отдельно в roadmap и
launch-документах.

## Основные риски и работа с ними

| Риск | Способ снижения |
| --- | --- |
| Слабое выполнение запроса или изменение личности | Детерминированный prompt builder, visual validation, correction/repeat и regression-кейсы для групповых фото |
| Дублирование оплаты или начисления | SHA-256, серверный ResultURL, идемпотентные order/ledger/receipt transitions |
| Ошибки состояния MAX и «молчаливые» кнопки | Явная state machine, owner walkthrough и профильные transport/UX-тесты |
| Потеря файлов или SQLite | Приватное хранилище, online backup, проверка восстановления и orphan/quick_check gates |
| Падение VPS или повторный runtime | systemd, один polling process, healthcheck и эксплуатационные runbooks |
| Неконтролируемые расходы и abuse | Бесплатная квота, rate/concurrency limits, budget guards и постепенное масштабирование |

## Реализовано и подтверждено

- Основной MAX-путь: фото и инструкция, preview с водяным знаком, Gallery,
  версии, correction и repeat.
- Публичный сайт `ravuna.ru` с HTTPS и юридическими страницами.
- «Пакет доступа Ravuna» за 49 ₽: две обработки и один оригинал без водяного
  знака.
- Серверное подтверждение Robokassa через ResultURL с идемпотентным начислением.
- Реальный production-платёж и последующая выдача оригинала.
- CI/CD, healthcheck, SQLite `quick_check`, backup/restore и orphan checks.

## Находится в работе

- Повышение качества сложных групповых изменений без потери узнаваемости.
- Накопление статистики instruction-following, времени, стоимости и ошибок.
- Внешние оповещения, регулярные recovery drills и коммерческая reconciliation.
- Подтверждение capacity-порогов перед переходом от одного VPS/SQLite runtime к
  очереди и объектному хранилищу.

## Итоговый статус

**Функциональный публичный MVP запущен, а ключевой путь оплаты подтверждён.** Это
не означает готовность к неограниченному масштабированию. Для первых
пользователей продукт работоспособен; рост аудитории должен идти постепенно с
контролем качества, стоимости, ошибок и стоп-условий.
